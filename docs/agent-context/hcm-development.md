# Справочник по разработке в SAP HCM (SIBUR HCM Development Digest)

Данный справочник содержит выжимку по разработке в модуле SAP HCM на основе учебного курса «Основы разработки для консультанта HCM». Используйте его при создании или модификации отчетов, расширении инфо-типов и настройке интерфейсов в HCM.

---

## 1. Логические Базы Данных (ЛБД)

ЛБД — это стандартный инструмент SAP для автоматического построения селекционного экрана и оптимизированной выборки данных по кадровым объектам. 

### Основные ЛБД в HCM:
1. **PNP** — классическая ЛБД для кадрового администрирования (без Concurrent Employment).
   * Основной узел: `PERNR` (выборка по табельным номерам).
   * Узел `PAYROLL` (для результатов расчета).
2. **PNPCE** — ЛБД для систем с активированным Concurrent Employment (совместительство).
   * Узлы: `PERSON` (личность), `GROUP` (группы ТН), `PERAS` (табельный номер и периоды).
3. **PCH** — ЛБД для организационного менеджмента.
   * Основной узел: `OBJEC` (объекты OM: O, S, C и периоды их действия).

### Управляющие события и команды ЛБД в отчетах:
* `GET pernr` / `GET peras` / `GET objec` — срабатывает при выборке каждого объекта. Данные текущей записи помещаются в глобальные структуры (например, `pernr-pernr`).
* `GET pernr LATE` — срабатывает после того, как все подчиненные данные по табельному номеру выбраны.
* `REJECT` — команда внутри блока `GET`, прерывающая обработку текущего табельного номера и переходящая к следующему.
* **Класс отчета (Report Class):** Настройка селекционного экрана ЛБД (отображение стандартных полей выбора) ведется в ракурсе `T599C` (транзакция `SE36` -> Классы отчетов).

## 2. Структура хранения данных по инфо-типам

В HCM данные хранятся по инфо-типам (IT) с разделением на кадровые данные (PA) и организационные данные (OM).

### 2.1. Инфо-типы PA (Кадровое администрирование)
* **Таблица БД:** `PAnnnn` (где `nnnn` — 4-значный номер инфо-типа, например `PA0001`).
* **Структура в ABAP:** `Pnnnn` (для типизации внутренних таблиц/структур, например `P0001`).
* **Ключ инфо-типа (пакет PAKEY):**
  * `PERNR` — Табельный номер
  * `SUBTY` — Подтип инфо-типа
  * `OBJPS` — Дополнительный идентификатор объекта (редко)
  * `SPRPS` — Индикатор блокирования записи
  * `ENDDA` / `BEGDA` — Период действия записи (ГГГГММДД)
  * `SEQNR` — Порядковый номер записи (для нескольких записей с одним ключом и периодом)
* **Информационные поля (пакет PSHD1):** `AEDTM` (дата изменения), `UNAME` (имя пользователя).
* **Кастомные поля расширения:** Размещаются во включаемой структуре `CI_Pnnnn`.

### 2.2. Инфо-типы OM (Организационный менеджмент)
* **Таблица БД:** `HRPnnnn` (например, `HRP1000`).
* **Табличная часть (для многострочных IT):** `HRTnnnn` (содержит поля `TABNR` и `TABSEQNR`).
* **Структура в ABAP:** `Pnnnn` (для типизации).
* **Ключ инфо-типа (пакет HRIKEY):**
  * `PLVAR` — Вариант плана (обычно '01')
  * `OTYPE` — Тип объекта (O — орг.единица, S — должность, C — квалификация и др.)
  * `OBJID` — Идентификатор объекта OM
  * `SUBTY` — Подтип
  * `ISTAT` — Статус планирования (обычно '1' — активный)
  * `BEGDA` / `ENDDA` — Период действия
  * `VARYF` — Вариативное поле ключа
  * `SEQNR` — Порядковый номер записи
* **Кастомные поля расширения:** Структура `CI_P1008` (в зависимости от IT) или через аппенды.

## 3. Чтение данных инфо-типов (Основные ФМ)

При отказе от ЛБД или необходимости довыборки данных в ABAP-коде используются стандартные функциональные модули:

### 3.1. Для инфо-типов PA (Кадровые данные)
Используется ФМ **`HR_READ_INFOTYPE`** (чтение данных с учетом полномочий и фильтрации):
```abap
CALL FUNCTION 'HR_READ_INFOTYPE'
  EXPORTING
    pernr           = lv_pernr
    infty           = '0008'
    begda           = lv_begda
    endda           = lv_endda
  TABLES
    infty_tab       = lt_p0008
  EXCEPTIONS
    infotype_not_found = 1
    others             = 2.
```

### 3.2. Для инфо-типов OM (Организационные данные)
* **`RH_READ_INFTY`** — чтение записей инфо-типа для объектов OM.
* **`RH_READ_INFTY_TABDATA`** — чтение табличной части OM инфо-типов (из таблицы `HRTnnnn` по значению `TABNR`).
* **`RH_STRUC_GET`** — выборка объектов OM по пути анализа (структурное считывание на основе путей из транзакции `OOAW`).

### 3.3. Признаки (Features)
* **`HR_FEATURE_BACKFIELD`** — чтение возвращаемого значения признака (настройки в транзакции `PE03`, например, признаков `MOLGA`, `UGR`, `ABKRS`).

## 4. Расширение инфо-типов и Пулы модулей

Логика работы экранов ведения инфо-типов (транзакции `PA20`, `PA30`, `PPOME`) инкапсулирована в программах пула модулей **`MPnnnn00`** (для кастомных расширений — **`ZPnnnn00`**).

### Структура инклюдов пула модулей (`MPnnnn00`):
* `MPnnnn10` — Определение глобальных данных, констант (аналог `TOP`).
* `MPnnnn20` — Модули PBO (Process Before Output) — подготовка данных перед выводом на экран.
* `MPnnnn30` — Модули PAI (Process After Input) — проверки и обработка пользовательского ввода.
* `MPnnnn40` — Подпрограммы (`FORM`).

### Основные экраны инфо-типов:
* `2000` — Одиночный экран ведения записи.
* `3000` — Обзорный список записей инфо-типа.
* `7000` — Экран для интеграции в портальные транзакции (например, `PPOME`).
* `**33` — Российские экраны (предпочтительно использовать именно экраны с окончанием `33`, например, `2033`).

### Процедура расширения инфо-типов:
1. **PA инфо-типы:** Расширение выполняется через транзакцию **`PM01`** (вкладка «Отдельный экран»). Поля структуры расширения `CI_Pnnnn` обязательно должны начинаться на **`ZZ`**. Настройка видимости полей ведется в ракурсе `T588M` (SPRO).
2. **OM инфо-типы:** Расширение выполняется через транзакции **`PPCI`** / **`PPCM`**. Управление видимостью полей настраивается программно внутри пула модулей.
3. **Ракурсы инфо-типов (соединение экранов):** Позволяет выводить поля одного инфо-типа на экране другого (настройка в ракурсах `V_T582V` и `V_T582W`, например, связка 0016 и 0109 для России). Требует реализации callbacks `CPREL_TO_PNNNN` и `PNNNN_TO_CPREL` в пуле модулей.

## 5. Расширения (User-Exits & BAdI) в HCM

Для кастомизации стандартной логики SAP HCM используются следующие механизмы:

### 5.1. Стандартные расширения (транзакция `CMOD`/`SMOD`):
* **`PBAS0001`** — Самый важный User-Exit для кадровых данных. Содержит ФМ для проверки значений инфо-типов до отображения и после сохранения (`EXIT_SAPFP50M_001` / `EXIT_SAPFP50M_002`).
* **`HRPTIM03`** — Расширение алгоритмов генерации лимитов присутствий/отсутствий.
* **`RHIV0001`** — Пользовательское определение нумерации объектов OM.

### 5.2. Поиск BAdI в коде HCM:
* **Классические BAdI:** Точка останова в отладчике ставится на метод `CL_EXITHANDLER=>GET_INSTANCE`. В параметре `EXIT_NAME` возвращается имя BAdI.
* **Новые BAdI:** Ищется инструкция `GET BADI` в коде. Внедрения ведутся через `SE18` / `SE19`.

## 6. Печатные и Экранные Формы

### 6.1. Adobe PDF Forms (транзакция `SFP`)
* **Интерфейс:** Определяет входящие параметры и типы данных из ABAP.
* **Контекст:** Связывает переменные интерфейса с полями отображения.
* **Шаблон:** Верстка выполняется в *Adobe LiveCycle Designer*.
* **Вызов из программы:** Выполняется через последовательность функций:
  1. `FP_JOB_OPEN` (открытие сессии печати).
  2. `FP_FUNCTION_MODULE_NAME` (получение имени динамического ФМ для формы).
  3. Вызов динамического ФМ (передача данных).
  4. `FP_JOB_CLOSE` (закрытие сессии).

### 6.2. Экспорт в MS Office (Excel/Word)
* **ZWWW** — Легаси-библиотека обертки над OLE (`ZWWW_OPENFORM`, `ZWWW_FILLFORM`). Медленная на больших объемах данных.
* **XSLT-трансформации** (`CALL TRANSFORMATION`) — Выгрузка в формате XML (очень быстро, поддерживает форматирование).
* **XLSX Workbench** (`ZXLWB_CALLFORM`) — Предпочтительный современный визуальный шаблонизатор для выгрузки в Excel (для Excel 2013+).

## 7. Утилитарные классы SAP HCM

Для оптимизации разработки и исключения циклов с прямыми запросами к БД/ФМ в проекте созданы специализированные утилитарные классы. Подробное описание и примеры использования приведены в сопроводительном [README.md](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/hcm_utility_classes/README.md).

### Список классов:
1. **[ZCL_HCM_PA_OBJ](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/hcm_utility_classes/zcl_hcm_pa_obj.abap)** — работа с кадровыми данными одного сотрудника (ФИО, паспорт, адреса, почта, логин, руководитель, подписанты).
2. **[ZCL_HCM_OM_OBJ](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/hcm_utility_classes/zcl_hcm_om_obj.abap)** — работа с одним объектом Организационного менеджмента (STEXT/1002 тексты, связи, пути анализа, атрибуты ИТ 1222). Обладает встроенным статическим кэшем.
3. **[ZCL_HCM_OM_OBJ_MASS](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/hcm_utility_classes/zcl_hcm_om_obj_mass.abap)** — массовые операции над множеством объектов OM (пакетное чтение путей анализа, наследование атрибутов, пакетное определение данных контроллинга BUKRS/WERKS/BTRTL по орг.структуре).
4. **[ZCL_HCM_OBJ_MASS](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/hcm_utility_classes/zcl_hcm_obj_mass.abap)** — смешанная массовая буферизация PA и OM (пакетное наполнение буфера ИТ перед вызовом `HR_READ_INFOTYPE` с помощью метода `fill_hr_infty_buffer`).
