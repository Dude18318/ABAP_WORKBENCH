# Playbook: Legacy Change

Используйте этот маршрут для багфиксов, небольших доработок и рефакторинга существующего ABAP-кода.

## Цель

Сделать минимально достаточное изменение без переписывания архитектуры отчета целиком.

## Алгоритм

1. Определите затронутые include/class/method и соседние зависимости.
2. Прочитайте локальный стиль кода перед правкой.
3. Меняйте только код, необходимый для задачи.
4. Если затронут SQL, ФМ, `CALL SCREEN`, persistence или authority check, оцените, должен ли этот вызов жить за DAO.
5. Если legacy-код нарушает правила СИБУР вне зоны задачи, не исправляйте его массово без явной причины.
6. Добавьте или обновите ABAP Unit только для измененной детерминированной логики.
7. В финале укажите, какие риски остались из-за legacy-ограничений.

## Decision Rules

| Если | Тогда |
| --- | --- |
| Правка в существующем процедурном блоке малая | Сохраняйте текущий стиль и минимальный diff |
| Внутри изменяемого блока есть `SELECT` в цикле | Исправьте локально, если это не раздувает задачу непропорционально |
| Для исправления нужен неизвестный `Z_*` объект | Примените [unknown-z-objects.md](unknown-z-objects.md) |
| Требуется переписать весь отчет ради чистой архитектуры | Остановитесь и запросите подтверждение пользователя |

## Не Делать

* Не переносите весь legacy-отчет на MVC/DAO только из-за маленькой доработки.
* Не меняйте форматирование целого файла без необходимости.
* Не удаляйте пользовательские или исторические изменения, если они не мешают задаче.
