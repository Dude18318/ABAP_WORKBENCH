# Playbook: Greenfield Report

Используйте этот маршрут для создания нового полноценного ABAP-отчета.

## Цель

Создать отчет в стиле СИБУР: читаемый, тестируемый, с разделением данных, сценария и UI.

## Алгоритм

1. Уточните входы: ТЗ, selection screen, источники данных, формат вывода, сценарии сохранения.
2. Начните со структуры из `src/boilerplate/`, если нужен полноценный отчет.
3. Разделите код по слоям: `lcl_app`, `lif_dao/lcl_dao`, `lcl_view`.
4. Все `SELECT`, ФМ, BAPI, `COMMIT WORK`, `CALL SCREEN`, authority checks держите за DAO.
5. Для selection screen используйте единую структуру параметров и нормализацию в app/main class.
6. Добавьте ABAP Unit для детерминированной логики: mapping, validation, filtering, preparation before save.
7. Если нужен `Z_*` объект без сигнатуры, примените [unknown-z-objects.md](unknown-z-objects.md).

## Decision Rules

| Если | Тогда |
| --- | --- |
| Пользователь просит маленький пример или spike | Допустима компактная структура без полного boilerplate |
| Отчет читает/сохраняет данные | DAO обязателен |
| Есть ALV/UI | View class отвечает только за отображение и UI events |
| Есть бизнес-правила из ТЗ | Покройте их тестами или явно объясните, почему тест невозможен |

## Не Делать

* Не пишите SQL в `lcl_app` или `lcl_view`.
* Не используйте `SELECT *` и `SELECT` в циклах.
* Не создавайте CDS/AMDP без прямого требования ТЗ.
