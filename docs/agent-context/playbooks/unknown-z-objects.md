# Playbook: Unknown Z Objects

Используйте этот маршрут для любых неизвестных `Z_*`, `Y_*` и других кастомных объектов SAP, если их сигнатуры нет в локальном контексте.

## Цель

Управлять незнанием явно: не блокироваться на мелочах, но и не выдавать предположения за факты.

## Где Искать

1. `docs/agent-context/references/tables/`
2. `docs/agent-context/references/classes/`
3. `docs/agent-context/references/function_modules/`
4. `docs/agent-context/references/types/`
5. `docs/agent-context/references/utility_classes/`
6. `docs/agent-context/references/hcm_utility_classes/`
7. Полный код в подпапках `full_code/`, только если краткого описания недостаточно.

## Decision Tree

| Ситуация | Действие |
| --- | --- |
| Сигнатура найдена в references | Используйте ее и не добавляйте TODO |
| Неизвестно поле/тип, но логика не критична | Продолжайте с предположением, добавьте `#TODO_SIGNATURE` |
| Неизвестны ключи таблицы, параметры ФМ/BAPI или направление параметров | Зафиксируйте блокер в `spec_analysis.md` и спросите пользователя |
| Объект влияет на сохранение, проводки, зарплату или права доступа | Не фантазируйте; запросите подтверждение |
| Объект упоминается повторно | Не плодите дубли в `missing_signatures.md`; обновите существующую строку |

## Формат TODO в Коде

```abap
" #TODO_SIGNATURE: Проверить сигнатуру объекта Z_OBJECT. Предположение: поле FIELD1 TYPE char10, ключ FIELD1.
```

## Формат missing_signatures.md

| Object | Type | Needed For | Assumption | Status |
| --- | --- | --- | --- | --- |
| `Z_OBJECT` | table/class/fm/type | Метод или требование | Что предполагается | open/resolved |

## Правила Уверенности

| Уверенность | Когда использовать | Поведение |
| --- | --- | --- |
| High | Есть reference или полный код | Кодить без TODO |
| Medium | Есть имя и понятный SAP-паттерн, но нет полной сигнатуры | Кодить с `#TODO_SIGNATURE` |
| Low | Нет ключей, типов или направления параметров | Остановиться и спросить |

## Не Делать

* Не выдумывайте точную сигнатуру без пометки.
* Не скрывайте предположения в финальном ответе.
* Не используйте unknown object в destructive/save flow без подтверждения.
