## 📋 Обзор классов и сценариев использования

### 1. [ZCL_READ_MULTIPLE_TEXTS](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/utility_classes/zcl_read_multiple_texts.abap)
* **Назначение**: Массовое (пакетное) чтение длинных текстов.
* **Когда использовать**: **Обязательно** к использованию, когда необходимо прочитать длинные тексты (заголовки/позиции заказов, тексты материалов, контрагентов и т.д.) для **множества объектов сразу**.
* **Почему это важно**: По правилам оптимизации  **категорически запрещено** вызывать `READ_TEXT` или `ZCL_TEXT_STATIC=>READ` внутри циклов `LOOP`. Вместо этого необходимо собрать все ключи текстов в таблицу и передать в данный класс для выполнения одного группового запроса.
* **Пример использования**:
  ```abap
  " 1. Заполняем таблицу заголовков текстов, которые нужно прочесть
  DATA(lt_thead) = VALUE zcl_read_multiple_texts=>ty_t_thead(
    ( object = 'EBAN' name = '001000005100010' id = 'B01' spras = 'R' )
    ( object = 'EBAN' name = '001000005200010' id = 'B01' spras = 'R' )
  ).

  " 2. Инициализируем класс и запускаем чтение
  DATA(lo_reader) = NEW zcl_read_multiple_texts( lt_thead ).
  lo_reader->read_any( ).

  " 3. Результаты находятся во внутренней таблице mt_texts
  LOOP AT lo_reader->mt_texts ASSIGNING FIELD-SYMBOL(<ls_text>).
    " <ls_text>-text содержит прочитанный текст в виде String
  ENDLOOP.
  ```

### 2. [ZCL_TEXT_STATIC](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/utility_classes/zcl_text_static.abap)
* **Назначение**: Статические методы для работы с одиночными текстами.
* **Когда использовать**: Для точечных операций чтения, записи, удаления или проверки существования текстов (вне циклов).
* **Основные методы**:
  * `READ` — одиночное чтение текста (возвращает `STRING`).
  * `SAVE` — сохранение текста (принимает `STRING`).
  * `DELETE` — удаление текста.
  * `EXISTS` — проверка существования.
  * `ITF2TEXT` / `TEXT2ITF` — преобразование форматов (внутренняя таблица ITF в строку и обратно).
* **Пример использования**:
  ```abap
  IF zcl_text_static=>exists( iv_name = '0010000051' iv_object = 'MATERIAL' iv_id = 'GRUN' ).
    DATA(lv_text) = zcl_text_static=>read( iv_name = '0010000051' iv_object = 'MATERIAL' iv_id = 'GRUN' ).
  ENDIF.
  ```

### 3. [ZCL_BDC](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/utility_classes/zcl_bdc.abap)
* **Назначение**: Облегчение работы с пакетным вводом (Batch Input / Call Transaction).
* **Когда использовать**: При необходимости программно вызвать транзакцию с заполнением экранов.
* **Вспомогательные методы**:
  * `BDC_DYNPRO` / `BDC_FIELD` — наполнение таблицы шагов BDC.
  * `CALL_TRANSACTION` — вызов транзакции с автоматической проверкой полномочий `S_TCODE` и поддержкой параметров пользователя для отладки.
  * `BDCMSG_TO_BAPIRET` — преобразование сообщений BDC-таблицы в стандартную структуру ошибок `BAPIRET2`.
  * `CURR_TO_CHAR` / `MENG_TO_CHAR` — форматирование сумм и количеств во внешнее текстовое представление для BDC.

### 4. [ZCL_REUSE_MAILER](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/utility_classes/zcl_reuse_mailer.abap)
* **Назначение**: Отправка электронных писем (на базе BCS-интерфейсов SAP).
* **Когда использовать**: Для отправки уведомлений, писем с вложениями, HTML-отчетов.
* **Основные возможности**:
  * Отправка писем внешним получателям (`ADD_RECIPIENT_MAIL`) или пользователям SAP (`ADD_RECIPIENT_UID`).
  * Добавление вложений разных типов (`ADD_ATTACHMENT`).
  * Преобразование таблиц ABAP в HTML-код (`CONV_TABLE_TO_HTML`) для вставки красивых таблиц прямо в тело письма.
  * Создание SAP Shortcuts (ярлыков для открытия транзакций в SAP GUI из письма).

### 5. [ZCL_SD_LONG_TEXT_EDITOR](file:///D:/SIBUR_AI/WORKBENCH/docs/agent-context/references/utility_classes/zcl_sd_long_text_editor.abap)
* **Назначение**: Визуальный редактор длинных текстов на экранах SAP GUI (обертка над `CL_GUI_TEXTEDIT`).
* **Когда использовать**: В кастомных диалоговых экранах, где требуется предоставить пользователю текстовое поле для ввода или просмотра форматированного многострочного текста.
* **Основные возможности**:
  * Конструктор принимает структуру заголовка текста `THEAD`.
  * Метод `SHOW` отображает редактор в контейнере или в отдельном диалоговом окне.
  * Метод `SAVE` сохраняет измененный текст в базу данных.
